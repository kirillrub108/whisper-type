# 05. Слой WinAPI

Это сердце проекта и самая опасная его часть: ошибки здесь не ловятся типами и часто не дают
исключений — вызов просто молча не срабатывает. Документ описывает каждую подсистему и те
грабли, ради обхода которых код написан именно так.

**Общее правило проекта:** все структуры объявляются явно через `ctypes.Structure` с
корректными для x64 полями, у всех функций проставлены `argtypes`/`restype`.
Без `argtypes` ctypes считает аргументы 32-битными и рвёт хендлы на x64 — это отмечено
комментарием прямо в коде ([overlay.py:156](../whispertype/overlay.py)).

## 1. Клавиатурный хук

**Файл:** [hotkey.py](../whispertype/hotkey.py)

```python
SetWindowsHookExW(WH_KEYBOARD_LL, proc, GetModuleHandleW(None), 0)
```

### Требование message loop

Низкоуровневый хук доставляется через очередь сообщений потока. Поэтому поток обязан крутить
`GetMessageW`/`TranslateMessage`/`DispatchMessageW` ([hotkey.py:146-152](../whispertype/hotkey.py)),
даже если сам никаких окон не создаёт. Остановка — `PostThreadMessageW(tid, WM_QUIT, 0, 0)`.

### Коллбэк обязан быть мгновенным

Windows отводит хуку ограниченное время (`LowLevelHooksTimeout`). Если превысить — система
**молча снимает хук**, и пользователь замечает это как лаги всей клавиатуры. Отсюда правило:
внутри `_ll_proc` только обновление множеств и `queue.put`, никакой работы.

### Ссылка на коллбэк

```python
self._proc = _HOOKPROC(self._ll_proc)   # hotkey.py:82
```

Хранится в атрибуте намеренно. Если объект коллбэка соберёт GC, Windows вызовет освобождённую
память. Та же схема применена в [overlay.py:220](../whispertype/overlay.py).

### Структура `KBDLLHOOKSTRUCT`

```python
("vkCode", DWORD), ("scanCode", DWORD), ("flags", DWORD),
("time", DWORD), ("dwExtraInfo", c_size_t)   # ULONG_PTR = 8 байт на x64
```

Последнее поле — `ULONG_PTR`, не `DWORD`. На x64 ошибка здесь сдвинула бы разбор.

### Проглатывание клавиш

Возврат `1` из хук-процедуры означает «событие дальше не пойдёт». Используется дважды:

- **Esc во время записи** ([hotkey.py:116](../whispertype/hotkey.py)) — иначе Esc закрыл бы
  диалог, в который пользователь диктует;
- **несущая клавиша комбо** ([hotkey.py:130-131](../whispertype/hotkey.py)) — иначе пробел из
  `Ctrl+Space` напечатался бы в поле ввода.

### Отсечение собственных событий

```python
if kb.flags & LLKHF_INJECTED:   # hotkey.py:103
    return CallNextHookEx(...)
```

Без этого наш собственный Ctrl+V, отправленный через `SendInput`, вернулся бы в хук.

## 2. Синтез ввода: SendInput

**Файл:** [inject.py](../whispertype/inject.py), секция «SendInput (x64)»

### Размер структуры `INPUT`

```python
assert ctypes.sizeof(c_void_p) != 8 or ctypes.sizeof(INPUT) == 40   # inject.py:94
```

На x64 `INPUT` обязан быть ровно **40 байт**: 4 байта `type` + 4 байта паддинга +
32 байта union. Если размер не совпадёт, `SendInput` молча ничего не сделает — ассерт ловит
это на старте, а не в проде.

### Два способа ввода

| Способ | Как | Когда применяется |
|---|---|---|
| `send_ctrl_v` | 4 события: Ctrl↓ V↓ V↑ Ctrl↑ | `inject.method = "clipboard"` (дефолт) |
| `type_text` | по символу с `KEYEVENTF_UNICODE` | `inject.method = "type"` |

`type_text` отправляет **не VK-коды, а UTF-16 code units** в поле `wScan` с флагом
`KEYEVENTF_UNICODE`. Символы вне BMP (эмодзи) дают суррогатную пару — два unit'а, что и делает
`utf16_units` ([inject.py:24-31](../whispertype/inject.py)).

Отдельно обрабатывается перевод строки ([inject.py:149-152](../whispertype/inject.py)):
Unicode-символ `0x0A` многие поля игнорируют, поэтому вместо него отправляется настоящий
VK_RETURN.

Ввод разбивается на пачки (`type_batch_size`, дефолт 16 символов) с паузой между ними —
приложения с медленной обработкой ввода теряют символы при отправке одним махом.

### Ожидание отпускания клавиш

```python
wait_keys_released(extra_vks, timeout=1.0)   # inject.py:119
```

Опрашивает `GetAsyncKeyState` по всем модификаторам плюс клавишам хоткея. Без этого
Ctrl+V придёт в окно как Ctrl+<зажатый модификатор>+V, и вставки не будет. По таймауту не
падает, а пишет предупреждение в лог и пробует вставить.

## 3. Буфер обмена

**Файл:** [inject.py](../whispertype/inject.py), секция «буфер обмена»

### Ретраи открытия

```python
def _open_clipboard(retries=10):     # inject.py:194
    for attempt in range(retries):
        if OpenClipboard(None): return True
        time.sleep(0.01 * (attempt + 1))
```

Буфер — глобальный разделяемый ресурс, и его регулярно держит открытым другой процесс.
Пауза нарастающая: 10, 20, 30 мс… — суммарно до ~0.55 с.

### Владение памятью

Тонкость `SetClipboardData`: **после успешного вызова handle принадлежит системе**, освобождать
его нельзя. Поэтому `GlobalFree` вызывается только на путях ошибок
([inject.py:244-251](../whispertype/inject.py)), а при успехе — нет.

### Восстановление прежнего содержимого

`paste_via_clipboard` ([inject.py:265-280](../whispertype/inject.py)):

```
снимок буфера → положить наш текст → Ctrl+V → пауза → восстановить снимок
```

Класс `ClipboardSnapshot` различает три ситуации:

| Ситуация | `text` | `restorable` | Что делаем после вставки |
|---|---|---|---|
| был текст | строка | `True` | вернуть текст |
| буфер пуст | `None` | `True` | очистить |
| было нетекстовое (картинка, файлы) | `None` | `False` | **не трогать** |

Третий случай важен: восстановить картинку мы не умеем, поэтому честнее оставить как есть и
записать в лог, чем затереть чужие данные.

Пауза `clipboard_restore_delay_ms` (дефолт 150 мс) нужна потому, что Ctrl+V асинхронен —
приложение-получатель ещё не успело прочитать буфер.

## 4. UIPI: почему вставка иногда невозможна

**Файл:** [inject.py](../whispertype/inject.py), секция «UIPI»

User Interface Privilege Isolation запрещает процессу отправлять ввод окну процесса с более
высоким **integrity level**. Проблема в том, что `SendInput` при этом возвращает успех —
текст просто не появляется.

`foreground_blocks_input()` ([inject.py:426-449](../whispertype/inject.py)) определяет это
заранее:

```
GetForegroundWindow → GetWindowThreadProcessId → OpenProcess
  → OpenProcessToken → GetTokenInformation(TokenIntegrityLevel)
  → GetSidSubAuthority(последняя) = RID уровня
```

RID: `0x2000` — medium (обычные программы), `0x3000` — high (запуск от администратора).

Особый случай: если `OpenProcess` не удался даже с
`PROCESS_QUERY_LIMITED_INFORMATION` — процесс почти наверняка повышенный, возвращаем `True`
([inject.py:438-442](../whispertype/inject.py)).

Разбор `TOKEN_MANDATORY_LABEL` сделан вручную: буфер приводится к указателю на `PSID`
(первое поле структуры), затем берётся последняя подавторитета
([inject.py:328-333](../whispertype/inject.py)).

**Обойти это нельзя** без запуска самой программы от администратора, что противоречит цели
проекта. Поэтому пользователь получает уведомление и текст в буфере.

## 5. Возврат фокуса окну

**Файл:** [inject.py](../whispertype/inject.py), секция «фокус окна»

### Правило Windows

`SetForegroundWindow` работает, только если вызывающий процесс **сам сейчас активен**. Иначе
система молча откажет (вернёт `FALSE` или, хуже, `TRUE` без эффекта).

Для меню трея условие выполнено: pystray перед показом меню делает своё окно активным
(`SetForegroundWindow(self._hwnd)` в его `_on_notify`) и обратно фокус не отдаёт.

### Проверка опросом, а не по коду возврата

```python
def _became_foreground(hwnd, timeout):   # inject.py:397
    while time.monotonic() < deadline:
        if foreground_window() == hwnd: return True
        time.sleep(0.01)
```

Вызов асинхронен, поэтому единственный надёжный способ узнать результат — опросить
`GetForegroundWindow`.

> **Историческая заметка.** В коде был вариант с `AttachThreadInput` (канонический приём
> обхода ограничения). Он был удалён: в тестовом окружении не срабатывал, а непроверенный
> код в этом слое хуже его отсутствия. Fallback «текст в буфер + уведомление» покрывает отказ.

### Фильтр окон оболочки

```python
_SHELL_WINDOW_CLASSES = {"Shell_TrayWnd", "Progman", "WorkerW", ...}   # inject.py:359
```

Пока пользователь ведёт мышь к значку в трее, активным окном успевает побыть панель задач.
Без фильтра фраза из истории вставлялась бы в неё. Класс окна берётся через `GetClassNameW`.

## 6. Слоёное окно индикатора

**Файл:** [overlay.py](../whispertype/overlay.py)

### Стили окна

```python
WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE
```

| Стиль | Зачем |
|---|---|
| `LAYERED` | попиксельная прозрачность через `UpdateLayeredWindow` |
| `TRANSPARENT` | клики проходят насквозь |
| `TOPMOST` | поверх остальных окон |
| `TOOLWINDOW` | не появляется в Alt+Tab |
| `NOACTIVATE` | **не забирает фокус** — иначе Ctrl+V ушёл бы в индикатор |

### Premultiplied alpha

`UpdateLayeredWindow` ждёт **BGRA с предумноженной альфой**, а Pillow отдаёт RGBA:

```python
rgb = (arr[:, :, :3] * alpha[:, :, None] // 255)          # overlay.py:282
bgra = np.dstack((rgb[:,:,2], rgb[:,:,1], rgb[:,:,0], arr[:,:,3]))
```

Без предумножения полупрозрачные края выглядят светящимся ореолом.

### Отрицательная высота DIB

```python
info.bmiHeader.biHeight = -_HEIGHT   # overlay.py:291
```

Отрицательное значение = строки идут сверху вниз (top-down DIB), как в массиве numpy. С
положительным картинка перевернётся.

### Перерегистрация класса окна

```python
if err != 1410:  # ERROR_CLASS_ALREADY_EXISTS      overlay.py:350
    raise OSError(...)
```

Класс окна регистрируется на процесс. Повторная регистрация после пересоздания окна вернёт
эту ошибку — она безобидна.

## 7. Single instance

**Файл:** [winutil.py](../whispertype/winutil.py)

```python
CreateMutexW(None, False, "Local\\WhisperType.single-instance")
# GetLastError() == ERROR_ALREADY_EXISTS (183) → экземпляр уже есть
```

Префикс `Local\` — namespace текущей сессии. Это осознанно: в терминальных сессиях у каждого
пользователя может быть своя копия, `Global\` требовал бы иных прав.

Если `CreateMutexW` вообще не удался, программа **продолжает работу без защиты**
([winutil.py:31-32](../whispertype/winutil.py)) — лучше запуститься, чем не запуститься.

Это же имя знает инсталлятор (`AppMutex`), поэтому установка поверх работающей программы
корректно предлагает её закрыть.

## Чек-лист при добавлении WinAPI-вызова

1. Объявить `argtypes` и `restype` — **всегда**, даже для «очевидных» функций.
2. Структуры — явно, с проверкой размера на x64, если он критичен.
3. Хендлы (`HANDLE`, `HWND`, указатели) — `wintypes.HANDLE`/`c_void_p`, не `DWORD`.
4. Коллбэки — хранить ссылку в атрибуте объекта.
5. Ошибку логировать с `ctypes.get_last_error()` (модуль должен быть загружен с
   `use_last_error=True`).
6. Если функция асинхронная — проверять результат опросом, а не по коду возврата.

## Проверь себя

1. Почему `assert sizeof(INPUT) == 40` полезнее, чем кажется?
   *(Ответ: при неверном размере `SendInput` не падает, а молча ничего не делает.)*
2. В буфере обмена лежит скриншот, программа вставляет текст. Что будет со скриншотом?
   *(Ответ: `restorable=False` → буфер не восстанавливается, скриншот теряется; в логе
   останется запись. См. [10-tech-debt.md](10-tech-debt.md).)*
3. Почему индикатору нужен `WS_EX_NOACTIVATE`, хотя он и так не принимает клики?
   *(Ответ: `TRANSPARENT` пропускает клики, но окно всё равно могло бы получить фокус при
   показе и увести Ctrl+V на себя.)*
