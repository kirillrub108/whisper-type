Пользовательская документация (установка, настройка, решение проблем) — в
[README.md](../README.md) в корне репозитория. Здесь — внутреннее устройство.

## С чего начать

**Первый день в проекте** → сразу [11-onboarding.md](11-onboarding.md), он ведёт по остальным
документам в правильном порядке.

**Нужно быстро сориентироваться** → [01](01-overview.md) → [02](02-architecture.md) →
[03](03-runtime-flows.md).

**Правите конкретный модуль** → найдите его в [04-modules.md](04-modules.md), оттуда ссылки
на профильные документы.

**Трогаете WinAPI** → [05-winapi.md](05-winapi.md) целиком, прежде чем писать код. Ошибки в
этом слое не дают исключений — вызов просто молча не срабатывает.

**Трогаете распознавание** → [06-speed.md](06-speed.md); связка «узкое окно +
`without_timestamps`» неочевидна, и её легко разорвать.

**Выпускаете версию** → чек-лист в [08-build-release.md](08-build-release.md#выпуск-релиза).
Версия живёт в **двух** местах.

## Что важно знать сразу

Три вещи, экономящие часы отладки:

1. **Тесты запускаются только через `python -m pytest -q`.** Прямой `pytest` не добавляет
   корень репозитория в `sys.path` → `ModuleNotFoundError: No module named 'whispertype'`.
2. **~62% кода не покрыто автотестами** — весь WinAPI, аудио и оркестрация. Это осознанное
   решение ([10](10-tech-debt.md#пробелы-в-тестировании)), но правки там проверяются руками.
3. **Раздел «Чего не ломать»** ([09](09-conventions.md#чего-не-ломать)) — список инвариантов,
   каждый из которых уже однажды был нарушен и стоил бага.
