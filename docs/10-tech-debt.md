# 10. Слабые места и техдолг

Документ намеренно недипломатичный: он нужен, чтобы новый разработчик не наступил на грабли и
понимал, где система хрупкая. Ничто из перечисленного не мешает программе работать — это
карта рисков, а не список багов.

Проверено на состоянии репозитория **версии 1.1.2** (коммит `caa0b8e`).

---

## Найденные расхождения код ↔ документация

### 1. Устаревшее сообщение в `build.bat`

```bat
echo Готово: dist\WhisperType.exe          # build.bat:44  ← неверно
...
echo Готово: dist\WhisperType\WhisperType.exe и ...   # build.bat:52  ← верно
```

Строка 44 (ветка «Inno Setup не найден») осталась со времён `--onefile`. После перехода на
`--onedir` файл лежит в `dist\WhisperType\WhisperType.exe`. Пользователь, у которого не
установлен Inno Setup, получит путь, по которому ничего нет.

**Влияние:** низкое, только сообщение. **Исправление:** одна строка.

### 2. README о записях в реестре

> «В реестр программа пишет только одну строку автозагрузки»
> — [README.md:267](../README.md)

Неточно: **инсталлятор** дополнительно создаёт
`HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\{2E17A9B0-…}_is1` — без неё
программа не появилась бы в «Установке и удалении». Утверждение верно про само приложение,
но читается как «в реестре после установки одна строка».

**Влияние:** низкое, вводит в заблуждение при ручной чистке.

## Мёртвый код

### `PhraseHistory.clear()`

[history.py:58-61](../whispertype/history.py) — метод существует и покрыт тестом
`test_clear_empties_and_persists`, но **в приложении не вызывается ниоткуда**. В меню трея нет
пункта «Очистить историю».

Два честных варианта: либо добавить пункт меню (функциональность напрашивается — история
хранит произнесённое пользователем, и возможность её стереть логична), либо удалить метод
вместе с тестом. Сейчас это код, который поддерживается, но не используется.

## Архитектурные риски

### 1. Зависимость от внутренностей faster-whisper

**Где:** [stt.py:48-66](../whispertype/stt.py), `encoder_window`

`adaptive_window` подменяет `faster_whisper.transcribe.pad_or_trim` — **внутреннюю функцию
библиотеки, не часть публичного API**. Любое обновление мажорной версии может её переименовать,
изменить сигнатуру или убрать вовсе.

Митигация в наличии: верхняя граница `faster-whisper<2` в
[requirements.txt](../requirements.txt) с комментарием, объясняющим причину. Плюс есть
fallback — если узкое окно бросит исключение, `_decode` повторит на полном
([stt.py:177-183](../whispertype/stt.py)).

Чего нет: fallback ловит **исключение**, но не молчаливое изменение поведения. Если в новой
версии `pad_or_trim` начнёт игнорировать аргумент `length`, приложение просто станет медленным
без единой ошибки в логе.

**Риск: средний.** Это цена ключевой оптимизации, и она была принята осознанно.

### 2. Дублирование константы 25 между модулями

```python
# config.py:270-276
# Больше stt.MAX_NARROW_SECONDS (сейчас 25) ...
if not 5 <= cfg.streaming.chunk_seconds <= 25:
```

```python
# stt.py:35
MAX_NARROW_SECONDS = FULL_WINDOW_FRAMES // FRAMES_PER_SECOND - WINDOW_MARGIN_SECONDS - 1
```

Значение вычисляется в одном месте, а проверяется литералом в другом. Импорт `stt` в `config`
сломал бы слоистость (`config` — базовый слой, не зависящий ни от чего), поэтому связь
поддерживается комментарием.

Если кто-то изменит `WINDOW_MARGIN_SECONDS`, `MAX_NARROW_SECONDS` пересчитается автоматически,
а валидация конфига — нет. Тест `test_max_narrow_seconds_still_narrows` поймает нарушение
инварианта в `stt`, но не рассинхронизацию с `config`.

**Риск: низкий, но реальный.**

### 3. Конкуренция за `Transcriber._lock`

Поток `stream` и финальное распознавание в `worker` делят один замок. При `_finish()` worker
ждёт, пока фоновый кусок досчитается — это `_stop_stream()` с `join(timeout=60.0)`
([app.py:232](../whispertype/app.py)).

60 секунд — не гипотетическая цифра: именно этот путь давал «зависание индикатора» на длинных
фразах до 1.1.2. Сейчас риск снижен ограничением куска до 25 с, но **архитектурно ожидание
осталось**: пользователь не может ускорить `_finish()`, если фоновый кусок оказался долгим.

Что было бы правильнее: отдельная модель для стриминга (удвоит память) или прерывание фонового
распознавания (faster-whisper этого не умеет). Оба варианта дороже проблемы.

### 4. Модель занимает память всё время

`large-v3-turbo` в `int8_float32` — порядка 1.5–2 ГБ RSS постоянно, независимо от того,
пользуется человек программой или нет. Выгрузка по таймауту не реализована: она вернула бы
многосекундную задержку при следующем нажатии, что противоречит цели проекта.

**Осознанный размен**, не дефект. Но на машине с 8 ГБ RAM это ощутимо.

## Функциональные компромиссы

### 1. Схлопывание может съесть настоящий повтор

`collapse_duplicated` не различает артефакт модели и намеренный повтор. Если пользователь
дважды подряд произнёс одно и то же длинное предложение (≥ 24 символов), останется одна копия.

Честно задокументировано в docstring [textproc.py:40-51](../whispertype/textproc.py). Событие
редкое, а альтернатива (повторное распознавание) стоила секунд на каждой сработке.

### 2. Нетекстовое содержимое буфера теряется

`paste_via_clipboard` восстанавливает только текст. Если в буфере была картинка или список
файлов — `restorable=False`, и содержимое **не восстанавливается**
([inject.py:278-279](../whispertype/inject.py)).

Пользователь, скопировавший скриншот и продиктовавший текст, потеряет скриншот. В логе
останется запись `в буфере было нетекстовое содержимое — восстановление пропущено`, но
уведомления нет.

Чинится сохранением всех форматов буфера — заметно более сложный код на `EnumClipboardFormats`.

### 3. Список галлюцинаций жёстко русскоязычный

`DEFAULT_HALLUCINATION_PATTERNS` ([config.py:67-84](../whispertype/config.py)) — 16 паттернов,
из них 12 русских («субтитры сделал», «продолжение следует»), взятых из типичных артефактов
Whisper на русских данных. Для другого языка список нужно писать самому.

Список редактируется в конфиге, так что это ограничение дефолта, а не кода.

### 4. Диктовка на смешанных языках хрупкая

При `language: null` язык определяется один раз на всю запись. `pick_language`
([stt.py:84-100](../whispertype/stt.py)) переопределяет его на лучший из `languages`, но
переключения **внутри** одной фразы нет.

Отдельная тонкость зафиксирована в комментарии к `vad.min_silence_duration_ms`
([config.py:117-119](../whispertype/config.py)): при крупном значении речь после короткой паузы
попадает в один сегмент, и если там сменился язык, Whisper обрывает расшифровку — **вторая
половина записи теряется целиком**. Дефолт 500 мс подобран именно из-за этого.

## Пробелы в тестировании

### Не покрыто автотестами вообще

| Модуль | Строк | Чем проверяется |
|---|---:|---|
| [inject.py](../whispertype/inject.py) | 449 (кроме 2 хелперов) | вручную |
| [overlay.py](../whispertype/overlay.py) | 362 | вручную |
| [hotkey.py](../whispertype/hotkey.py) | 161 | вручную |
| [app.py](../whispertype/app.py) | 428 | вручную |
| [tray.py](../whispertype/tray.py) | 165 | вручную |
| `AudioRecorder` (класс) | ~150 | вручную |

Это **~62% кодовой базы**. Решение обоснованное — мокать WinAPI значит тестировать моки, — но
последствие нужно принимать всерьёз: регрессии в этих модулях ловятся только человеком.

Особенно чувствителен `app.py`: там живёт state machine и порядок операций в `_finish()`,
ошибка в котором уже приводила к пользовательскому багу. Логика оркестрации в принципе
тестируема при вынесении подсистем за интерфейсы — но это заметный рефакторинг.

### Не проверено end-to-end

**Путь «клик по истории → возврат фокуса → вставка»** невозможно воспроизвести из фонового
процесса: `SetForegroundWindow` требует, чтобы вызывающий процесс сам был активен. Условие
выполняется только при реальном клике по меню трея.

Код написан по документации pystray и проверен по частям, но целиком путь верифицируется
исключительно живым пользователем.

Эти проблемы **уже исправлены**, но объясняют, почему код выглядит именно так. Не откатывайте
эти решения.

| Проблема | Симптом | Решение |
|---|---|---|

## Если бы делать заново

Не рекомендация к рефакторингу, а точки, где решение неочевидно:

1. **Вынести оркестрацию из `app.py` за интерфейсы.** 428 строк с state machine и нулевым
   покрытием — самый большой источник регрессий.
2. **Единый источник для `MAX_NARROW_SECONDS`.** Например, вынести константы окна в отдельный
   модуль без зависимостей, который могут импортировать и `config`, и `stt`.
3. **Пункт «Очистить историю»** — метод уже написан.
4. **Сохранение всех форматов буфера обмена**, если найдётся пользователь, которого это
   действительно задело.
