# WhisperType

Локальный голосовой ввод для Windows: зажали хоткей → сказали → отпустили → текст появился в активном поле ввода любого приложения. Полностью офлайн (faster-whisper `large-v3-turbo`, int8, CPU), без API-ключей, без прав администратора.

## Установка

**Готовый exe:** запустите `build.bat` (нужен Python 3.11 и `py`-launcher), заберите `dist\WhisperType.exe`, положите куда удобно и запустите. Установка не требуется.

**Из исходников:**

```bash
py -3.11 -m venv .venv && .venv/Scripts/pip install -r requirements.txt && .venv/Scripts/python launcher.py
```

## Первый запуск

1. Появится иконка в трее (серая — идёт загрузка).
2. Модель (~1.6 ГБ) скачается автоматически с HuggingFace в `%LOCALAPPDATA%\WhisperType\models` — придёт уведомление. После этого интернет больше не нужен.
3. Иконка станет синей («готов»). Нажмите **Ctrl+Space**, говорите, нажмите ещё раз — текст вставится в поле в фокусе.
4. `Esc` во время записи — отмена. Автозагрузка включается чекбоксом в меню трея.

Состояния иконки: серая — загрузка; синяя — готов; красная — запись; жёлтая — распознавание; тёмно-красная с «!» — ошибка (см. лог).

## Конфиг

`%APPDATA%\WhisperType\config.json` (создаётся при первом запуске; правки применяются после перезапуска):

| Параметр | Дефолт | Смысл |
|---|---|---|
| `log_level` | `INFO` | DEBUG/INFO/WARNING/ERROR/CRITICAL |
| `sounds` | `true` | Звуковые сигналы старт/стоп/ошибка |
| `model.repo` | `deepdml/faster-whisper-large-v3-turbo-ct2` | Репозиторий модели на HF |
| `model.compute_type` | `int8_float32` | Квантизация CTranslate2; `int8` быстрее, но грубее |
| `model.cpu_threads` | `6` | Потоки инференса (= физическим ядрам) |
| `model.beam_size` | `5` | 1–5; 5 — точнее, 1 — быстрее |
| `model.language` | `"ru"` | Язык диктовки. `null` — определять автоматически, но это **вдвое медленнее**: автоопределение стоит отдельного прохода энкодера |
| `model.languages` | `["ru","en"]` | Кандидаты при автоопределении: чужой язык переопределяется на лучший из списка |
| `model.initial_prompt` | `null` | Затравка: задаёт стиль пунктуации и подсказывает термины |
| `model.hotwords` | `null` | Имена и термины, которые нужно расслышать точно |
| `model.temperature_fallback` | `true` | Повторные попытки при провале порогов качества |
| `model.compression_ratio_threshold` | `2.4` | Выше — расшифровка признаётся зациклившейся |
| `model.log_prob_threshold` | `-1.0` | Ниже — расшифровка признаётся неуверенной |
| `model.no_speech_threshold` | `0.6` | Отсечение пустых записей |
| `model.normalize_audio` | `true` | Нормализация громкости и снятие DC-смещения |
| `model.adaptive_window` | `true` | Сужение окна энкодера под длину фразы — главное ускорение на CPU (turbo: ~1 с вместо ~4 с). Подробности — в разделе про скорость |
| `vad.enabled` | `true` | Обрезка тишины по краям (Silero) |
| `vad.threshold` | `0.35` | Ниже — VAD охотнее считает тихий звук речью |
| `vad.min_silence_duration_ms` | `500` | Пауза, разделяющая сегменты. Крупные значения опасны: речь после короткой паузы попадает в один сегмент, и при смене языка Whisper обрывает расшифровку — вторая половина записи теряется |
| `vad.speech_pad_ms` | `400` | Запас по краям речи, чтобы не срезать первый слог |
| `overlay.enabled` | `true` | Индикатор записи в правом нижнем углу экрана |
| `streaming.enabled` | `true` | Распознавать длинную диктовку кусками прямо во время речи |
| `streaming.chunk_seconds` | `8` | С какой длины резать кусок (5–29). Режет только по настоящей паузе, поэтому сплошная речь не рвётся посреди слова |
| `audio.input_device` | `null` | `null` — системный микрофон; имя или индекс устройства |
| `audio.max_record_seconds` | `120` | Максимум записи (защита от залипшего хоткея) |
| `audio.min_record_ms` | `300` | Записи короче игнорируются |
| `hotkey.mode` | `toggle` | `push_to_talk` (зажать) или `toggle` (нажать дважды) |
| `hotkey.combo` | `ctrl + space` | См. «Настройка хоткея» |
| `hotkey.cancel` | `esc` | Отмена текущей записи |
| `inject.method` | `clipboard` | `clipboard` (Ctrl+V) или `type` (посимвольно) |
| `inject.clipboard_restore_delay_ms` | `150` | Пауза перед восстановлением буфера |
| `inject.type_batch_size` | `16` | Символов в пачке для метода `type` |
| `inject.type_batch_delay_ms` | `5` | Пауза между пачками |
| `inject.append_space` | `false` | Пробел в конце вставки |
| `inject.strip_final_period` | `false` | Убирать финальную точку |
| `hallucination_patterns` | список | Фразы-галлюцинации Whisper, вырезаются регистронезависимо |

## Настройка хоткея

`hotkey.combo` — клавиши через `+`: `"right ctrl"`, `"ctrl+alt+space"`, `"f9"`, `"ctrl+shift+d"`.
Имена: `ctrl/lctrl/rctrl`, `alt/lalt/ralt`, `shift/lshift/rshift`, `win`, `space`, `esc`, `enter`, `tab`, `f1`–`f24`, буквы `a`–`z`, цифры, `numpad0`–`9`, `home/end/pageup/pagedown/insert/delete`, стрелки.

Несущая (последняя) клавиша комбинации перехватывается и не доходит до активного окна: при дефолтном `ctrl + space` перестаёт работать Ctrl+Space в других программах (например, переключение раскладки). Если это мешает — смените хоткей.

## Логи

`%LOCALAPPDATA%\WhisperType\logs\app.log`, ротация 5 × 2 МБ. Открыть папку — из меню трея.

## Troubleshooting

- **Не вставляет текст.** Чаще всего окно в фокусе запущено от администратора (UIPI) — придёт уведомление, текст останется в буфере, вставьте Ctrl+V вручную. Либо вы ещё держали модификаторы в момент вставки — приложение ждёт их отпускания до 1 с, отпускайте хоткей полностью. Для терминалов/игр, не принимающих Ctrl+V, поставьте `inject.method: "type"`.
- **Не слышит / пустой результат.** Проверьте микрофон в меню трея → «Микрофон». Убедитесь, что запись длиннее ~0.3 с. В `app.log` видно длительность и результат каждой записи.
- **Тормозит (распознавание дольше пары секунд).** Whisper штатно прогоняет через энкодер окно в 30 секунд независимо от длины фразы. Приложение это обходит (`adaptive_window`): окно сужается до «длина записи + 4 с», но не уже 12 с, а таймкоды при узком окне отключаются (`without_timestamps`) — именно они заставляли модель придумывать продолжение за пределами записи и дублировать текст. Остаточный редкий самоповтор схлопывается на уровне текста без повторного распознавания. Замеры на Ryzen 5 7500F (turbo, `int8_float32`, `language: "ru"`, по 3 прогона):

  | Запись | Полное окно | `adaptive_window` |
  |---|---|---|
  | «привет» (тихо и громко) | 3.8–4.1 с | **1.1 с** |
  | фраза 5.5 с | 4.7 с | **1.3 с** |
  | фраза с терминами 8 с | 4.2 с | **1.5 с** |
  | диктовка 15 с (со `streaming`) | 4.5 с | **~0 с** (хвост уже распознан) |

  Порог 12 с снизу обязателен: на окне короче ~8 с модель зацикливает одиночное слово («Привет.» ×10). Запас 4 с проверен на записях 5–15 с; сужение опирается на внутреннюю функцию faster-whisper, поэтому версия библиотеки в `requirements.txt` ограничена сверху. Если распознавание всё же медленное — проверьте, что `language` задан явно (`null` стоит отдельного прохода энкодера, вдвое дороже), `cpu_threads` равен числу ядер, а `adaptive_window: true` не выключен. Модель побыстрее ценой точности: `small` даёт ~1.0 с даже на полном окне, но требует заполненного `initial_prompt` (см. ниже).

  Чем длиннее запись, тем больше окно энкодера и тем дороже проход. Это лечит `streaming`: куски распознаются прямо во время речи, и после остановки остаётся только хвост. Ожидание тогда почти не зависит от длины диктовки, но решает именно порог `chunk_seconds` — при слишком большом значении короткая-средняя диктовка не режется вовсе:

  | Запись | порог 25 с | порог 12 с | порог 8 с |
  |---|---|---|---|
  | 20 с | 4.2 с | 2.3 с | 1.4 с |
  | 40 с | 4.5 с | 2.3 с | 1.6 с |

  Платой служит фоновая работа процессора во время речи (для 40 с диктовки при пороге 8 с — около 10 с счёта), но ждать её не приходится: она идёт, пока вы говорите.

  Снижать `beam_size` смысла нет: разница между 5 и 1 — около 0.2 с. `compute_type: "int8"` вместо `int8_float32` даёт лишь 5%.
- **Настройки из конфига не применяются.** Признак — в логе строка `не удалось прочитать config.json ... использованы дефолты`. Частая причина: файл сохранён с BOM-меткой (так делают Блокнот Windows и `Out-File -Encoding utf8` в PowerShell). Приложение читает конфиг как `utf-8-sig` и BOM переносит, но если правите файл сторонним редактором — сохраняйте в UTF-8 без BOM. Проверить применение настроек проще всего по строке `загрузка модели ...` в логе: там видны реальные `repo`, `compute_type` и `threads`.
- **Ошибается в словах.** Сначала посмотрите в логе строку `язык ...` для своей фразы: если язык определяется неверно, задайте его жёстко — `model.language: "ru"`. **Для модели `small` обязательно заполните `model.initial_prompt`** — без него английские термины превращаются в кашу («дакр и пайтан, а кот храню на гитоп» вместо «Docker и Python, а код храню на GitHub»); с подсказкой те же слова распознаются верно. Дальше по убыванию эффекта: `model.beam_size: 5`, `model.compute_type: "int8_float32"`, `model.normalize_audio: true`. Отдельные имена можно добавить в `model.hotwords`. Если максимальная точность важнее скорости — переключитесь на полную модель `model.repo: "Systran/faster-whisper-large-v3"`: она заметно точнее turbo на русском, но декодер в ней глубже, поэтому распознавание идёт в несколько раз дольше.
- **Английские слова записываются кириллицей.** Отдельные термины внутри русской фразы («Docker» → «DACR») лечатся перечислением их в `model.initial_prompt` — это подсказка модели о лексике, а не команда. Целые английские фразы turbo и так пишет латиницей даже при `language: "ru"`, менять язык на `null` ради этого не нужно. Если английская часть записи пропадает целиком — дело не в языке, а в `vad.min_silence_duration_ms`: см. описание параметра выше.
- **Съедает первый слог или конец фразы.** Понизьте `vad.threshold` (например до `0.25`) и/или увеличьте `vad.speech_pad_ms`. Полностью выключить обрезку тишины — `vad.enabled: false`.
- **Хоткей не срабатывает.** Иконка красно-коричневая с «!» — хук не установился, перезапустите приложение. Некоторые античиты блокируют низкоуровневые хуки в играх.
- **Второй запуск.** Показывает сообщение и выходит — приложение уже висит в трее.
